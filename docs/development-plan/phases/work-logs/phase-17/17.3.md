### 2026-10-30 — CI: the Cypress binary was never installed on a node_modules cache hit
- **Branch:** `chore/17.3-framework-skeleton` — a fix in the same pull request, because the required check `e2e` blocked it.
- **Problems / blockers / findings:** the four `e2e tests` shards failed with "the Cypress binary is missing". The `install` action restores
  `node_modules` from a cache and skips `npm ci`, whose postinstall downloads the binary, and the separate Cypress cache has no entry in the
  repository (`gh cache list`). So any pull request with a code change fails `e2e` while the `node_modules` cache is warm. This one is the first
  since the cache of 16.4 was created; the earlier code pull requests ran `npm ci` themselves. It is not caused by the skeleton.
- **Decisions / deviations from the plan:** the `e2e-shard` job gets a step `npx cypress install` after the Cypress cache step. It does nothing
  when the binary is cached, and the cache step saves the binary after the first green run.
