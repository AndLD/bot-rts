### 2026-10-30 — the layer map generated from the profile file
- **Branch:** `chore/17.6-layer-map` — done. Built on top of the 17.5 branch while its CI ran, then rebased onto the integration branch after
  17.5 was merged.
- **Decisions / deviations from the plan:**
  - **The source.** The `layers` role of `harness-profile.json`: `scope` (the tracked files the map covers), `excluded`, `core`, `domain`,
    `adapter`, `profile`, `state`, `entry`, as globs (`*` inside a folder, `**` across folders, a leading `!` removes). The tools add what they
    know: the vendored copy is CORE; the profile file, the lock, the profile document and every `bindings.md` are PROFILE (this closes
    H-20261019-23: the profile file cannot be missing from the map again); the folder of a staged framework source (the lock's `path` source)
    is outside the map.
  - **The commands.** `harness layers` prints the map; `harness check layers` fails on a file in the scope that no layer claims or that two
    layers claim, naming the file; `npm run docs:check` runs it.
  - **The CORE list stays until 17.8.** Design §8.2 says the `core-files` block goes away because the vendored tree is CORE. That holds
    only after 17.8 moves the core documents into the framework. Until then the project's CORE documents are the `layers.core` entries (a
    path, with `sections` and numbers when only some sections are CORE), and the CORE scan reads them from the profile file. The one allowed
    overlap is a file with a `sections` entry (`AGENTS.md`: CORE in sections 1 and 7, ENTRY for the rest). Design §8.2 says so now.
  - **Managed blocks.** The map sits in `docs/quality-reviews/harness/bindings.md` between `<!-- harness:begin layers -->` and `<!-- harness:end
    layers -->`. A generator with a `block` writes only that region, and the lock keeps the hash of the region alone, so the text around it
    stays free (tests: an edit around the block passes, an edit inside fails, a file without the markers is refused). 17.8 uses the same
    mechanism for the entry file.
  - **Classification changes.** Four files had two classes in the old map. `docs/harness-framework/README.md` and `design.md` are STATE only (the
    old map also called the README an index); `GAME-DESIGN.md` is DOMAIN, `DEVELOPMENT-PLAN.md` is STATE. `docs/harness-framework/design.md`
    was in no class and now is STATE. Everything tracked that the scope covers is in exactly one layer (220 files).
  - **The bindings name roles (H-20261019-22, second half).** The four `bindings.md` files no longer spell `develop` or `main`: the
    measurements use `origin/<integration>`, the probes and prompts say "the integration branch". The stale sentence on budgets (H-20261019-21)
    now points to the approved table.
