# 12.4 — The pre-push gate cannot start its database in a worktree, so sessions bypass it.

**Status:** ✅ · **Agent:** C2 · **Size:** 3 SP

**The pre-push gate cannot start its database in a worktree, so sessions bypass it.** Found by the harness review of 2026-10-30 (H-20261030-02 in `docs/quality-reviews/harness/2026-10-30.md`): a push from a worktree that needs the database (a change of `api` or of a shared file) runs `npm run db:up`, which fails while the main checkout holds ports 5432 and 6379, so six pushes of Phase 16 used `git push --no-verify` and ran some checks by hand (`phase-16-log.md`). The per-worktree ports of 15.12 (`.env`) exist, but no session set them. The same step also fails when Docker Desktop is not running (the Phase 0 log records it, and it was off on 2026-10-30): `db:up` then prints only Docker's own error, which says nothing about what to do. Expected: (1) before `db:up`, the pre-push setup (`.githooks/pre-push` and `scripts/local-gate.mjs`; it stays in this repository, design §3.4 of the framework) finds out which case it is in and acts on it: a database already answers on the configured port, so it uses that one; Docker is not running (`docker info` fails), so it stops with "start Docker Desktop (`open -a Docker`), then push again"; the port is taken by another checkout and nothing answers, so it stops with the two lines to put in `.env`; a push that needs no database still needs no Docker; (2) one rule for the bypass, written once: `--no-verify` is the owner's, for an emergency, and is recorded in the task log; `.githooks/pre-push`, `docs/testing/known-issues.md` and `docs/testing/README.md` say the same, and a row of `docs/engineering/rule-checks.md` holds it (_partly_ until the Bash guard of 17.11 refuses the flag). Deliver `node --test` tests of the setup decision with stand-ins for the Docker and port checks (database answers; Docker not running; port free; port taken by another checkout; no database needed), a push from a worktree while the main checkout runs its database, and a push with Docker Desktop off
