### 2026-11-02 — the contracts, the host adapter and `check values`
- **Branch:** `chore/17.9-contracts-github-host` — done. The claim was opened first.
- **Decisions / deviations from the plan:**
  - **Contracts.** `core/contracts/{stack,runtime,host}.md` hold the role lists of design §4.1 to §4.3 without the preset columns (a preset
    names tools, which core must not). Their machine form is `profile/manifest.schema.json`: the structure in the schema subset the profile
    reader implements, and `x-roles` with the kind of every role per axis (`required`, `optional`, `logic`, `logic-optional`). The new
    `harness check adapters` holds every adapter that has a `manifest.json` to its axis (required roles filled, no unknown role, the files
    and modules a role names exist, `terms` a pattern). An adapter folder without a manifest is skipped for now: node-ts and claude-code
    arrive in 17.10 and 17.11, and 17.14's conformance suite makes the manifest mandatory.
  - **Merge guard is optional** in the host contract (`logic-optional`): it is needed only when `host.protection` is false. Design §4.3 says so.
  - **Several stacks.** An `adapters.stacks` entry may be `{ "adapter": …, "packages": [folders] }`; `check profile` fails when a project with
    several stacks leaves one without folders, and when two stacks claim one folder or one inside the other.
  - **The host adapter** (`adapters/host/github/`): `protect.mjs` (`buildRuleset`, `detectProtection`, `protect`; the `gh` runner is a parameter
    so the tests stand in for it), `workflows.mjs` (`readTriggers`, `readJobNames`, `isWorkflowFile`), `templates.mjs` and the templates
    `ci.yml` and `release.yml`. Values in a template are `<%= path %>` because a workflow is full of `${{ … }}`, which the Markdown
    renderer takes for its own placeholders. The stack adapter will supply the job ids that the aggregator needs (17.10).
  - **Protection detection.** The host is asked for the rulesets of the repository: readable means available; the answer "Upgrade to GitHub
    Pro or make this repository public" means not available (the answer Phase 0 recorded); anything else is an error, not a guess. The new
    profile role `host.protection` (default true) must agree with it, or `harness host protect` fails and changes nothing; with both saying
    no it does nothing and says so.
  - **`repository.protectionScript` is gone.** The protection is `harness host protect`, a command and not a project value, so the Role
    binding line lost that clause and the protection rule of the entry file lost "the branch-protection script". For `host.protection:
    false` the rule has its own text (the hooks hold it; an agent never merges while a required check is not green), through a new
    `{{#unless}}` block of the template engine. The admin-bypass rule exists only with protection.
  - **`harness check values`** replaces `scripts/harness-profile.test.mjs` (deleted with `scripts/protect-branches.sh`). Its file lists moved
    to the profile role `checks.roleOnlyPaths` (scripts, hooks, workflows, and the engineering, operations and testing documents); the rules
    are the old tests' own, and the new one: a workflow that lists the coverage packages fails (a `needs:` line names jobs and is exempt).
    `ci.yml` of this repository reads the packages with `harness profile get coveragePackages` in the two places that listed them.
  - **The CORE scan joins the adapters' `terms`** (the manifest field), reported as "<axis> adapter <name> term". The github adapter's are
    `github`, `gh` and `.github/`.
  - Rule-map row 43 and the harness bindings name `harness host protect`; the generated core rows of the map are 17.11's.
- **Problems / blockers / findings:**
  - A sync that changes the template engine renders the managed blocks with the engine it replaces; a second `harness sync --local` renders
    them with the new one. The first run left a literal `{{#unless …}}` in `AGENTS.md`, which `check generated` caught.
  - The `host protect` command was run against a stand-in `gh` only. Running it against the repository would change its live ruleset, which is
    the owner's call, so it was not run.
- **Proofs:** `npm run test:framework` (196 tests; among them the stand-in `gh` request of the profile file, the triggers and a missing
  required-check job failing `check values`, two stacks claiming one folder failing `check profile`, the rendered templates passing
  `check values`); `npm run test:scripts`; `npm run docs:check`.
