### 2026-11-02 — one engine behind `init`, `bootstrap`, the template and `BOOTSTRAP.md`
- **Branch:** `chore/17.13-bootstrap` — done. The claim was opened before the work.
- **Decisions / deviations from the plan:**
  - **The engine** (`tools/lib/bootstrap.mjs`). `completeProfile` makes the complete profile file from the answers. The answers win; then come
    the defaults of the questions, the new `defaults` of the selected adapters' manifests, and `profile/starter.json`; the title and the term lists
    are derived. `scaffoldPlan` is the pure function from that profile and a framework tree to the scaffolded files. The managed files come from
    the sync engine (`vendor`, extracted from `sync`), not from the pure plan, so a sync and a bootstrap cannot render them differently (design
    §6.1, amended).
  - **The defaults of a new project live in `profile/starter.json`, not in the schema.** A first try put them in the schema (a default host,
    branches, paths). That changed existing projects: a project with no host silently selected GitHub, and `check profile` no longer caught a
    missing branch. The tests caught both, so the schema keeps its required roles without defaults. The one schema change is that
    `documents.harnessBindings` is optional, since the lines that cite it already fall away without it.
  - **The scaffold.** The core files are the templates of `core/templates/scaffold/`. Their target paths are roles (`scaffold.json`).
    - The core files: the entry file (reading map and empty managed blocks), the README, the stack file, the rule-to-check map, and the plan index.
    - The plan's first phase is the open-ended phase (`plan.openEndedPhaseNumber` 1, no task yet), with its work log, because the Git rules need
      an open-ended phase.
    - Also: the changelog and its fragments folder, a releasing guide, and the harness-review bindings as a stub that the first review fills.
    - Each axis gains the optional logic role `scaffold-files`, written into the contracts. node-ts adds `.nvmrc`, `.prettierignore`, a
      `package.json` whose `prepare` installs the hooks, and an empty lock file (so `npm ci` works). claude-code adds `CLAUDE.md` and the
      settings. github adds the CI workflow (the frame with the stacks' jobs in place of its comment) and the release workflow.
    - A file that several parts name is a list of lines (`.gitignore`); any other duplicate is an error.
  - **Placeholder scripts.** The procedures need `commands.lint` and `commands.testCoverage`, so node-ts gives `npm run lint`, `npm test` and
    `npm run test:coverage`. The scaffolded scripts for them only say that no tool is installed yet. This keeps CI green on a project with no code,
    and the project replaces them when it adds its tools.
  - **The front ends.**
    - `harness init` reads the existing profile file first (a template's, or an earlier run's), then the flags and `--set`, then asks the
      questions no flag answered, offering defaults. A missing required answer fails before anything is written.
    - `harness bootstrap` runs the engine on the file as it is.
    - `harness template <dir>` builds the template repository. Its lock records the source and lists the template's own files (`template`:
      README and `BOOTSTRAP.md`), which the bootstrap replaces or removes. `BOOTSTRAP.md` is distributable.
  - **Git.**
    - The order follows the design: the root commit on the integration branch, or a new integration branch made from a commit the host
      created; then the production branch; then `core.hooksPath`.
    - The first push of both branches is the owner's step, with `git push --no-verify`. The pre-push guard refuses protected branches, and the
      shell guard refuses `--no-verify` from an agent. The bootstrap prints this step.
    - A re-run on a bootstrapped project is refused unless `--force`.
  - **Fixes found on the way.**
    - A folder source outside the project (an absolute path in the lock) was joined onto the project root by the vendored check and the CORE
      scan. It is now resolved, and the CORE scan leaves such a folder to its own repository.
    - The plan summary's total line started at Phase 0. It now starts at the first phase.
    - `checkAll` and `report` moved to `checks.mjs`.
- **Problems / blockers / findings:**

    artifact download when a project has no coverage packages. The framework's proof (its Phase 1, task 1.5) runs them.
  - The interactive path is tested with piped answers, not in a real terminal.
