### 2026-10-30 — revision: standalone fork (owner's question in chat)
- **Branch:** `docs/17.1-framework-design` — revised and pushed; pull request #256 still waits for the owner's acceptance, not merged.
- **Decisions / deviations from the plan:** the owner asked that a project can become a standalone fork instead of staying updatable from
  the framework. The lock of the first version could not express it: its only escape was a temporary per-file override. Added as design §1.5:
  - a lock `mode` (`pinned`, default, or `detached`) and a `base` that records the fork point;
  - `harness detach` and `init --detached`;
  - in detached mode the vendored check and the edit guard are off, the CORE scan runs in the project, `sync` refuses and `sync --local`
    regenerates the managed files, and `diff` compares with the fork point;
  - the MIT notice stays and is checked;
  - re-attaching (a three-way merge from `base`) is left out of the first release, but `base` keeps it possible;
  - a fork of the framework repository, for a variant several projects share, needs no new mechanism: projects pin to the fork's URL.
  `bot-rts` stays pinned. 17.4 grows from 3 to 5 SP; 17.13 and 17.18 cover the detached case. Phase 17 is 66 SP.
- **Problems / blockers / findings:** none.
- **Next step:** the owner reviews pull request #256 again; on comments, revise and stop; on merge, start 17.2 in a fresh session.
