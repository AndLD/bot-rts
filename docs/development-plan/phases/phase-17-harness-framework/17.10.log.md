### 2026-11-02 — the gate driver, the node-ts preset and the neutral coverage
- **Branch:** `chore/17.10-stack-node-ts` — done. The claim was opened first; the work began on top of 17.9's branch while its CI ran, and moved
  here once 17.9 merged.
- **Decisions / deviations from the plan:**
  - **The split.** Core: `tools/lib/gate.mjs` (`harness gate`: the refs of a push, the changed files, routing to the owning stack, the
    documentation checks, the project's steps, the run), `coverage.mjs` (`harness coverage check-changed` and `merge`, the gate on the neutral
    summary, the shard naming) and `scaffold.mjs`. Stack adapter node-ts: `gate.mjs` (the plan, ported from `planGate`), `coverage.mjs`
    (merge and summary), `ci-jobs.mjs`, `manifest.json`. The scripts `local-gate.mjs`, `local-gate-lib.mjs`, `check-changed-coverage.mjs`,
    `merge-coverage.mjs` and `merge-coverage-lib.mjs` and their tests are gone from `scripts/`; their tests moved with them.
  - **What stayed project-specific became the profile role `gate`.** `outside` (the CI configuration and the agent's settings, which no check
    looks at), `isolated` (scripts, documents and the vendored framework, which cannot change a package's code, so they never trigger the full
    run), `needs` and `prepare` (the packages whose tests need a database, and the module that gets it ready: `scripts/local-gate-database.mjs`
    of 12.4, which now exports `prepare`), and `steps` (script tests, framework tests, and the generated-files check with its diff and hint).
    The plan's old `isShared`, `isOutsideTheGate`, `needsDatabase` and the generated step are these.
  - **The summary has no dependency.** The merge no longer needs `istanbul-lib-coverage`: Istanbul's own rules for the four metrics are
    written out in `coverage.mjs` (lines by the most-hit statement that starts on one, percentages rounded down), and a test compares the result
    with the library where it is installed (it is here, and they agree). So the `verify` job of CI no longer installs dependencies, and the
    framework repository needs none for the preset.
  - **H-20261030-09:** a push that changes documentation runs `harness check all` first, so the link and path checks are no longer skipped; a
    push that changes no file runs nothing.
  - **H-20261030-03:** `stack.md`, the profile's rows, `README.md` and `docs/testing/README.md` say that the local gate holds the changed
    files whose related tests ran (a package with none is judged by CI), and that CI holds the package totals and every changed file.
  - **The stack role "ignore files"** is in the node-ts manifest (`.prettierignore`, and `.eslintignore` when present). `harness check
    scaffold` fails when one does not exclude `harness/`; the format step of the plan runs `npx --no-install prettier`, and relies on that
    exclusion instead of a list of vendored paths.
  - **The CI job layout** of node-ts (`ci-jobs.mjs`) and the aggregator of the host template (`verify` merges the coverage with `harness
    coverage merge` and applies the changed-file gate) form one workflow that passes `check values`; a test builds it. This repository's
    own `ci.yml` stays its own.
  - The hook is still `.githooks/pre-push` and ends with `exec node harness/tools/harness.mjs gate`; the thin Git hooks come with 17.11.
