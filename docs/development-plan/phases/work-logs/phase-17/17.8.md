### 2026-11-02 — the core documents, the managed rule blocks and `check generated`
- **Branch:** `chore/17.8-core-documents` — done. Two sessions: the first (2026-10-31) moved the documents, wrote the rule templates and the
  generator and stopped on its usage limit with the work uncommitted; the second took the working tree over, checked it against the task and
  finished it.
- **Decisions / deviations from the plan:**
  - **The documents** of design §3.2 moved with `git mv` into the staging folder's `core/` and are vendored: the method (`core/method/`), the
    plan method with `phases.md` and the templates `index-template.md`, `phase-template.md` and `task-log-template.md`, the definition of
    done and the guiding principles (`core/plan/`), the review index and the code and harness review methods with `report-template.md` each
    (`core/reviews/`), and the changelog-fragment format (`core/templates/changelog-fragments.md`). The `_template.md` names became names
    that say what each template is. The inbound links (67, by the first session's count) point to `harness/core/…`; the outbound ones (26)
    became role names, and a new framework test (`core-documents.test.mjs`) holds that no link leaves `core/`. The profile's document map
    follows; `documents.method` defaults to the vendored method.
  - **The rule blocks.** `AGENTS.md` §1 and §7 (up to the session-protocol stub) are the managed blocks `non-negotiables` and `git-rules`,
    rendered from `core/rules/non-negotiables.md` and `core/rules/git.md` (`entry.mjs`). Each rule carries a stable id, 26 in all
    (`nn.*`, `git.*`, `agent.*`), which a test fixes so that a renamed id is a deliberate change; 17.11 cites them in the rule map. The
    Role binding line needed two new roles, `plan.openEndedPhaseNumber` and `repository.protectionScript`.
  - **Strict blocks.** The renderer leaves out a line whose placeholder has no value, which in a rule block would drop half a rule without
    a word. The entry blocks therefore refuse to render when a role they name is empty, and name the roles. They are generated for a project
    with a document map (`documents`), which the rules link; a profile without one gets none, as a profile without `layers` gets no layer map.
  - **The lock** keeps one hash per block (`<path>#<block>`), so one file holds several blocks.
  - **`harness check generated`** (new): the task's acceptance names it and design §6.3 defines it, so it is built here rather than in 17.12.
    It renders every managed file and block again and compares; unlike `check vendored` (hashes in the lock) it also catches a block left
    stale in a detached copy, which its test shows. It runs in `check all`, right after `vendored`.
  - **CORE without a list.** `layers.core` is empty: the layer map counts the entry file's blocks as CORE where the framework is in use, taken
    from the generator registry rather than from the lock, so the first sync that adds a block writes a true map. A file with CORE blocks or
    CORE sections may share one other layer; two others now fail (before, any number was let through). The harness bindings and design §8.2
    say so.
  - **The two neutral wordings** of design §3.1: "no new untyped public boundaries (the stack's lint rule names them)" and "no debug printing
    left in committed code (use the logger)".
  - **The local-database step** of method §6 applies only where the profile has the database commands (`commands.dbUp`, `dbMigrate`,
    `dbSeed`), an optional role group; the schema says so. The `finish-phase` procedure is 17.12's; design §8.1 already gives it the same
    condition ("not applicable" otherwise).
  - **The complexity markers** are a standard, optional task property of the plan method, its new section 7 (appended, so no anchor moves):
    the scale, the `Agent` column of open tasks, done tasks exempt, the range in the index, the conformance rule, re-rating, on or off.
    `phases.md` (anatomy, the "Rated" rule, the conformance list), the phase template (an `Agent` column) and the index template (the range
    column and the generated markers of the summary and the contents) follow.
