### 2026-10-30 — vendoring built, `harness/` synced from the staging folder
- **Branch:** `chore/17.4-vendoring` — done.
- **Decisions / deviations from the plan:**
  - **The tools.** `tools/harness.mjs` is the command line, and `tools/lib/` holds `tree.mjs` (walk, SHA-256, byte-identical copies that
    keep the file mode), `lock.mjs` (the lock, the profile file and its hash, the selected adapters), `source.mjs` (a folder or a Git tag) and
    `vendor.mjs` (`sync`, `checkVendored`, `diff`, `override`, `detach`). They are plain Node with no dependencies, written for Node 20 (CI)
    and Node 22.
    - `generators.mjs` is the registry of the managed files. It is empty: 17.5 adds the profile document, and later tasks add the rest.
      `sync --local` regenerates whatever the registry holds.
  - **Commands:** `sync [--from] [--to]`, `sync --local`, `check vendored`, `diff`, `override`, `detach`. `override <path> --reason --issue`
    was added so that an override does not need a SHA-256 computed by hand; design §1.3 only says the lock may list one.
  - **The lock** (`harness.lock.json`): `framework`, `mode`, `version`, `source`, `adapters`, `reason` and `base` (detached), `files`,
    `managed`, `profile`, `overrides`, and `seen` (Git sources: the commit of every version taken).
    - A folder source is `{ type: "path", location }`; its version is that of its `framework.json`.
    - A Git source is `{ type: "git", url, tag, commit }`. A plain path is a folder source, so a local repository is given as `file://`.
      The tag is `<version>` or `v<version>`. `seen` refuses a version whose tag now points to another commit.
  - **Detach** moves `files` to `base`, the fork point (framework, source, version, hashes), and sets `source` and `version` to null.
    `diff` fetches the fork point's content from `base.source` when it is reachable, and lists the paths when it is not.
  - **While the source is a folder** of this repository, `check vendored` also compares that folder with the lock. So the source and the
    copy must change in the same pull request, as design §1.3 asks.
  - **This repository:**
    - The profile file names the adapters: `node-ts`, `claude-code`, `github`. The stack entry is `{ "adapter": "node-ts" }`; 17.9 adds
      its packages.
    - `harness/` holds 25 files: the distributable paths and the three selected adapters, tests included, since `tools/` is distributable.
    - `npm run harness -- <command>` runs the tool, and `docs:check` runs `harness check vendored` first.
    - The pre-push hook runs the vendored check on every push, before the local gate and its documentation-only skip.
    - The local gate treats `harness/` and the lock as tooling, which runs the framework tests and not the full run (H-20261030-04).
    - `.prettierignore` lists `harness` and `harness.lock.json`.
    - The link check skips `harness/`: its links are copies of the source's, which resolve only at the source.
  - **Rules:** `AGENTS.md` §9 gets the rule "never edit `harness/`", with rule-map row 96 (enforced). Method §7 and rule-map row 83 name the
    vendored copy and its lock among the files regenerated after a rebase (H-20261030-04).
    The profile names the framework, its adapters and the `harness` commands.
  - `tools/lib/.gitkeep` went, since the folder now has files.
