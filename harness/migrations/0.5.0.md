# Migration to 0.5.0 from 0.4.0

## What changed for a project

- **Quiet output** (the context optimization, Phase 6). The framework's commands and hooks are quiet by default: `harness check all` prints the problems and one line (`N checks passed`), `harness check <name>` one line on a pass; the steps of the pre-push gate and the project checks (`checks.project`) write their output to a file and print nothing on a pass, and on a failure the path of the file and the failing lines, at most `output.maxLines` of the profile file (default 40). `--verbose` restores the full output of `check` and `gate`: **a script of the project that reads the output of a passing `check all` or `gate` must pass `--verbose`.**
- **Quiet commands of a stack** (optional). The profile roles `commands.lintQuiet`, `typecheckQuiet`, `formatQuiet`, `testQuiet` and `testCoverageQuiet` (the same check with the output reduced to the failures and a summary); the optional stack-adapter role `quiet-commands` gives them as defaults (both presets fill it; a minor addition to the stack contract, still version 2). The local gate runs the quiet variant of its test and lint steps unless `--verbose` is given, and the procedures cite the quiet variants. A project that sets none gets the plain commands, so nothing breaks; a new project from `harness init` has them. Since `0.5.0-dev.1` (I-31): the node-ts preset also defaults `typecheckQuiet` (`npm run --silent typecheck`) and `formatQuiet` (`npm run --silent format -- --log-level warn`), and its manifest says that the test defaults are for a single package. **From a workspaces root** (the root script is `npm run test --workspaces`) npm takes the flags after `--` and Jest never sees them, so the default prints as much as the plain command; the project writes `testQuiet` as `npm run --silent test --workspaces --if-present -- --reporters=summary --silent` and `testCoverageQuiet` the same way. That form was proven by hand in the consumer's take of `0.5.0-dev.1` (bot-rts, −75% of the output of the test step), not by the preset: the preset's default is unchanged and stays the single-package one, so a workspaces project sets the form itself.
- **Output budgets and the step report** (a change of the meaning of the method and of the procedures `run-flow`, `start-task`, `open-pull-request` and `end-session`: the procedures are a `contract.change`, decided as such; method section 8 and its line of section 4 are the owner's decision of 2026-11-07, not a `contract.change`). The method has a new section 8 (read with a filter, quiet variants, short pull request bodies, commit messages, log entries and closing messages, long text in a file of the plan) and a matching line in its definition of done. The step prompts of a flow (`core/plan/flow-step-prompts.md`) get a `budget` section and a `report` section with a schema (Status, Merged, Decisions, Deviations, Next step, Recommendations) capped at 30 lines and 2,400 characters; `harness flow report-check <file>` checks a saved report. The procedures are regenerated by `harness sync`.
- **Orchestrator restart** (a change of the meaning of `run-flow` and of the runtime contract's `context` role). A flow setting `orchestratorLimits.context` (50% of the orchestrator's window by default, beside `reuseLimits`), and a handoff entry in the flow's log (`### … — handoff: <why>` with State, Decisions, Next step, Waiting for), which `harness flow check` holds; `harness flow status` and `dispatch` print the orchestrator's context against the limit and a cache hint. A flow without the setting takes the default; an existing flow may add `"orchestratorLimits": { "context": 50 }`.
- **Delegated reading.** The step prompts of `tasks`, `consumer-take` and `triage-fix` steps gain a `delegate` paragraph (a large log, a long diff or a research of sources goes to a subagent that returns at most 10 lines; never a decision, a write or a merge); `start-task` and the runtime contract's `subagent` executor say the same. Rendered from the framework's copy; nothing to do.
- **`harness flow audit <n>`** (optional) reports where the tokens of a flow went, from the transcripts of its sessions. It needs the new optional runtime role `transcripts` (a minor addition to the runtime contract, still version 2; the Claude Code preset fills it); a runtime without it says the audit cannot run. Since `0.5.0-dev.1` (I-32) the audit finds the command-line workers of a flow too: it also reads a worker's id from its "step ended" entry (`Worker: cli <id>`), and splits a session that several steps reused by step, with the times of its turns and the ends of the steps in the log. The `locate` row of the runtime role `transcripts` takes a session id of any of three kinds: a desktop-app session, a command-line session by its id, or a worktree by its name (the Claude Code preset's `locate` finds a transcript by id in any project folder). A runtime adapter of the project's own that fills `transcripts` should accept the command-line id; nothing breaks if it does not, the audit then lists those workers as missing.
- **`harness check notes`** is part of `harness check all`: it fails when a note of the `migrations` folder has no line in the section "The notes" of its `README.md`, or a line has no note. A project without that section is not checked (I-25).
- **`flows.permissions`** (optional profile role, `{ "mode", "allow" }` in the runtime's own words): the default of a flow whose settings have no `permissions` of its own, which wins; `harness flow dispatch` takes it and `harness check flows` checks it (I-27).
- **Fixes.** `harness plan-write on` and `off` say to run the project's formatter on the settings file when its lint checks formatting (I-26); `harness flow status` reads the take of a version that a later take superseded as done (I-28); `harness flow estimate`, `gate` and `sample` take `--plan` in any case (I-29); the tests no longer fail on the tree that `harness release` leaves before its commit (`measureReview` skips a tracked file the work tree no longer has, I-24); the procedure `update-framework` names the services the project's gate needs (a database, a container runtime) in its verify step, and the agent says in its report which it started (I-23).

## Required actions

1. **Take the version.** Run `sync` on a branch of its own, then `node harness/tools/harness.mjs migrate` if the `sync` did not start it. No script runs; every new role and setting has a safe default, so a project of `0.4.0` that sets nothing passes `check all` and its procedures cite the plain commands.
   Check: `node harness/tools/harness.mjs check all` exits 0, and `migrations.version` in `harness.lock.json` is `0.5.0`.
2. **If a script of the project reads the output of a passing `check all` or `gate`** (a CI step that greps it, for one), add `--verbose` to that call.
   Check: the script gives the same result as before the take. A project with no such script has nothing to do.

A project that took `0.5.0-dev.1` takes this version the same way; the changes since it are the node-ts quiet defaults and the workspaces form (I-31) and the audit of command-line workers (I-32), both optional.

## Optional actions

- Set the quiet commands in the profile file (`commands.lintQuiet`, `typecheckQuiet`, `formatQuiet`, `testQuiet`, `testCoverageQuiet`; the values of the project's stack are in `adapters/stack/<stack>/manifest.json`, `defaults.commands`, and a project with its own commands writes its own), then run `harness sync` so the procedures cite them. Measured in the consumer's take of `0.5.0-dev.1`: the Jest quiet options cut the output of the test step by 75% (in a workspaces root only with the form above); the pytest options are not proven against a real project yet.
- Add `"orchestratorLimits": { "context": 50 }` to the settings of a flow file to set the restart threshold of its orchestrator.
- Set `flows.permissions` in the profile file to give every flow's workers one permission mode.
- Run `harness flow audit <n>` on a finished flow to see where its tokens went (the command-line workers are counted since I-32).
- A project whose root script runs the tests of its workspaces sets `testQuiet` and `testCoverageQuiet` to the workspaces form above.

## How to verify

```bash
node harness/tools/harness.mjs check all
node harness/tools/harness.mjs probes 0.4.0 0.5.0
```
