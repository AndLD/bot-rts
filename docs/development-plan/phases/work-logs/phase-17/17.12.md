### 2026-11-02 — the first set of procedures, packaged as skills
- **Branch:** `chore/17.12-procedures` — done. The claim was opened first; the work was written on 17.11's tree while its CI ran.
- **Decisions / deviations from the plan:**
  - **The set** (`core/procedures/`): `start-task`, `end-session`, `open-pull-request`, `finish-phase`, `release`, `harness-review`, `code-review`. They
    are the steps of the method's session protocol and the bindings' start prompts; the rules stay in the entry file and the method, and a
    procedure links them (design §8.1, "two owners avoided"). `new-adapter` is not in the set: it needs `core/contracts/new-adapter.md`, which is
    17.14's, and is added there. The "add an endpoint, a migration, a catalogue key" procedures are this project's own (`docs/procedures/`, design
    §8.1) and are not part of this task.
  - **Format.** Frontmatter `name`, `description` (the trigger, "Use when …"), `invocation` (`auto` or `explicit`), optional `paths`; a body that
    names roles and commands (`{{commands.lint}}`, `{{rel:documents.method}}`). `finish-phase`'s local-database step is in an `{{#if
    commands.dbUp}}` block, so it is "not applicable" without the database commands (design §8.1). A role a body needs outside such a block
    and the profile lacks fails the render, naming the procedure and the role.
  - **Packaging** is the runtime adapter's role `procedure-packaging` (`packaging.mjs`): `.claude/skills/<name>/SKILL.md`, with `name` and
    `description`, and `disable-model-invocation: true` for an explicit procedure. The skills are managed files, one generator per procedure and
    selected runtime, so `harness sync` writes them and `harness check generated` fails on a stale or missing one (tests: an edited skill, a
    removed one, a procedure changed in the framework without a sync).
  - **The reading-map fallback** is the managed block `procedures` of the entry file (a table "When … / Follow the procedure"), generated for every
    project, with or without a runtime. It links the vendored procedure files; their `{{…}}` placeholders name roles of the profile, which the
    reader resolves in the profile document, section Commands. This repository's `AGENTS.md` has the block after its reading map.
  - The harness bindings say where the skills and the Git hooks are now.
