### 2026-10-30 — the profile file at the root; `docs/profile.md` generated from it
- **Branch:** `chore/17.5-profile-file` — done.
- **Decisions / deviations from the plan:**
  - **The file.** `harness-profile.json` is at the root and holds every value that `docs/profile.md` stated: the project, the repository, the
    adapters, the coverage gate (`coverageGate`, folded in from `scripts/coverage-threshold.json`, which is gone), the quality-gate prose, the
    required checks and a note per check, the branches, the paths, the plan conventions, the API, languages, versions, commands, the four
    term lists (`terms`), the bounded contexts and the document map. Design §8.3 called the gate `quality.coverageGate`; it is the top-level
    `coverageGate`, since the Jest configs and the coverage tools read it by that name.
  - **Schema and reader.** `profile/harness-profile.schema.json` types every role and gives the defaults (`repository.host`,
    `paths.profileFile`, `paths.profileDocument`); `required` lists the roles a project must have, and `additionalProperties: false` refuses a
    role the schema lacks. The tools implement the subset of JSON Schema that it uses (`tools/lib/profile.mjs`), with no dependency.
    `harness check profile` runs it and also checks the two rules the subset cannot say (a stack entry is a name or an object with an
    `adapter`, and the profile document is not the profile file). `harness profile get <role>` keeps the old interface; the shell files and the
    release workflow use it. The tools no longer look under `scripts/` for the file.
  - **The document.** `profile/roles.md` is a Markdown template, and `docs/profile.md` is its rendering (managed file, hash-locked, regenerated
    by `harness sync` and `harness sync --local`). The template has `{{role}}`, `{{link:role}}`, `{{rel:role}}`, `{{#if}}` and `{{#each}}`; a
    line whose role has no value is left out, so an optional role (the API, the languages, the contexts) needs no switch. A value may cite
    another role. The numbered sections keep today's anchors (`#2-quality-gates`, `#3-branches-and-merging`, … `#10-document-map`).
    Differences from the old text: a neutral preamble, links labelled with their path from the document, the coverage figure bold as a whole,
    and the required-check job names written once (in `requiredChecks`, with the prose in `requiredCheckNotes`).
  - **Tests that went.** The test that compared the required checks with the table is gone (the table is generated), and so is the test of the
    old command line; `scripts/harness-profile.mjs` stays as the reader of the repository's scripts, now over the vendored reader. Tests that
    stay until 17.9: the branch triggers of the workflow, no literal profile value in scripts and workflows, and the protection request.
  - **Readers moved.** The Jest configs, `check-changed-coverage.mjs`, `merge-coverage.mjs`, the CORE scan and the product-knowledge check read
    the profile file; the term lists are no longer parsed from fenced blocks of the Markdown (the generated document still shows them, for the
    review commands). The link check skips a link with a template placeholder.
  - `docs:check` runs `harness check profile` after the vendored check.
- **Problems / blockers / findings:** none. Not done here, by design: `harness check values` (17.9) takes over the tests that stay, and
  `harness layers` (17.6) takes the layer map.
