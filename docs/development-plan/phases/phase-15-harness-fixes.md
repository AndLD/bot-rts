# Phase 15 — Harness fixes (58 SP)

**Status:** 🟡 In progress · **Branches:** see the [implementation log](#implementation-log) · **Work log:** [phase-15-log](./work-logs/phase-15-log.md)

Fixes the findings of the first harness quality review ([report of 2026-10-17](../../quality-reviews/harness/2026-10-17.md)) that
the owner triaged as **fix now** (its follow-up table, section 13). This phase is step 2 of the
[harness-framework plan](../../harness-framework/README.md#step-2-refactor-and-fix-the-docs-and-harness): that plan gives the
reasons, the rules for doing the fixes (its §2.3) and the exit criteria; this file holds the tasks. The phase makes the harness
true, enforced and ready for several agents before Phase 10. It also prepares the extraction of the framework (step 3 of that plan):
the profile, the split of `AGENTS.md`, and closing the export blockers.

**Rule changes.** Starting the phase approves its task pull requests (`AGENTS.md` §7.5). The owner decided every change of a
rule's meaning that this phase makes before it started (the work log, entry of 2026-10-18, "decisions before the start"); those
tasks merge like any other. A change of meaning that those decisions do not cover asks the owner before merging.

**Execution order:** one serial line, one task at a time (owner decision 2026-10-18): the tasks are too tightly coupled for
parallel agents, and the fixes that make parallel work safe (15.11, 15.12) are part of this phase.
15.1 → 15.2 → 15.3 → 15.8 → 15.5 → 15.6 → 15.7 → 15.4 → 15.9 → 15.11 → 15.12 → 15.13 → 15.10 → 15.14.
The values come first (15.1). The split of `AGENTS.md` comes next (15.2, 15.3), because later tasks edit the moved text.
The status-marker model (15.8) comes before the tasks that write markers (15.5, 15.4). The split of §12.5 (15.10) is last before
the re-review, because it renumbers a section that many documents cite.
