# 12.7 — An agent that resumes a phase reads the whole phase file, and a finished task is logged twice.

**Status:** ✅ · **Agent:** C1 · **Size:** 2 SP · **Log:** [12.7.log.md](./12.7.log.md)

**An agent that resumes a phase reads the whole phase file, and a finished task is logged twice.** Found by the closing harness review of 2026-11-03 (finding H-20261103-05): the resuming probe P2 read about 7,200 words before its first action (budget 6,000), most of them the rows of Phase 17's finished tasks; and 15 of the 23 entries of the Phase 17 log restate a task's own log, because the session-start hook reads the next step only from the phase log. Expected: an agent reads the phase index and the one task it works on, and each fact is logged once. **Fixed by the framework's `0.2.0`** (its tasks 3.10, 3.12: a phase becomes a folder with a generated index, a file per task and the task's log beside it). (1) Take `0.2.0` from `0.1.1` with the framework's procedure `update-framework` and its migration notes, not with steps written here; `0.1.2` is skipped on purpose, so this is the framework's first chained migration, and anything that goes wrong becomes a task of the framework's open-ended phase. Take the development version first, before the framework's final tag. (2) The owner's choices beyond the migration: also split Phase 17 (finished by then), with the framework's split command, as the example of a large phase; and turn on upstream reporting at `ask` (`reports.upstream` in `harness-profile.json`, the framework's task 3.16), so a framework defect found here is drafted as a report after a search for the same problem and posted with the owner's approval. Verified by the checks the migration notes name, no broken link into the split phases, and probe P2 within its budget.
