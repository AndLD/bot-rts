# I-2 — The client runs a Next.js version with known critical vulnerabilities.

**Status:** ⬜ · **Agent:** C1 · **Size:** 1 SP · **Area:** Unclassified · **Reported:** — · **Formerly:** 12.6

**The client runs a Next.js version with known critical vulnerabilities.** Found on 2026-11-02 when the local e2e build stopped with a security notice of Next.js, and confirmed by `npm audit`: Next.js 16.0.0 to 16.4.0, which `client/package.json` allows and the lock file installs (16.4.0), is affected by two critical advisories, unauthenticated remote code execution in the Image Optimization API with SVG files ([GHSA-2464-fhr4-w9xw](https://github.com/advisories/GHSA-2464-fhr4-w9xw)) and in `use cache` functions that return typed arrays ([GHSA-673q-mjm6-r5xr](https://github.com/advisories/GHSA-673q-mjm6-r5xr)), and one high, a denial of service in the App Router with Server Actions ([GHSA-p3m5-59mp-jv5r](https://github.com/advisories/GHSA-p3m5-59mp-jv5r)); 16.4.1 to 16.4.3 are published. The client's code uses none of the three features (no `next/image`, no `use cache`, no server actions), but whether `next start` serves the image endpoint anyway is not checked, so the task does not wait for that answer. Expected: `next` (and any package pinned to its version) raised to the newest patched 16.4 release in `client/package.json` and the lock file, `npm audit` no longer reporting these advisories, the build and every client check green. The other findings of `npm audit` are out of scope. Deliver the upgrade with the client's unit tests, typecheck, build and the e2e suite green, and a changelog fragment in `docs/product-knowledge/changelog.d/` (a `Security` entry)
